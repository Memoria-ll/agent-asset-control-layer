# 2026年9月9日の改善要求への対応

[総合改善インプット](integrated-improvement-input-2026-09-09.md)と[利用方針更新](mcp-first-onboarding-and-asset-relations.md)を、会話とMCPで導入・日常操作を完結させる方針として実装しました。同日追加された[Skill・Workflow・モデル・出力の設計](skill-workflow-model-and-export-design.md)も反映しています。既存の人間用UIも維持しています。操作手順は[運用ガイド](mcp-operations.md)、製品の契約は[開発要件v15](../agent-asset-control-layer-requirements.md)に記載しています。

## 同日の追加設計への対応

- 初期ContextはRule本文とSkillの説明一覧を持ちます。本文・補助ファイル・参照先は固定した改訂で個別取得し、候補の提示・取得・使用報告を分けます。[段階的取得テスト](../tests/progressive-skills.test.ts)と[公開API・CLIテスト](../tests/progressive-mcp.test.ts)で確認します。
- 初回整理はAIの分類根拠と原文から出力への対応を必須にしました。1原文からWorkflow・Role・Skillへ分割でき、切り替えと復元は全出力の改訂を検証します。未確定部分は切り替えを止めます。[導入テスト](../tests/onboarding.test.ts)で中断・復元も検証します。
- モデル未指定では起動引数からモデルを省きます。報告された実モデルを別に保存し、モデルの必須条件は開始報告と工程の進行・完了で確認します。準備時の資産と設定を保った別Snapshotへ実モデルの条件を解決します。[モデル比較テスト](../tests/progressive-metrics.test.ts)で指定と実モデルの集計も区別します。
- `skill.steps`の新規保存を廃止しました。旧データは読めますが、担当や工程の実行指示として展開しません。
- 相談・作成と出力の[組み込みSkill](../server/builtin-skills.ts)を追加しました。作成支援と初回整理で同じ分類基準を使います。
- [出力処理](../server/export.ts)は1時点の改訂・関係・設定・ハッシュを固定します。単独出力にはローカルのWorkflow工程、Role、資料、補助ファイルを含めます。[出力テスト](../tests/export.test.ts)でCoreへ接続せず遷移・差し戻し・完了を検証します。

## 利用方針更新への対応

接続設定の導入は`aacl_onboarding_connect`で行えます。対応するRuntimeの既存設定を保持し、AACLの接続先と案内を追加します。退避した設定本文は資産として公開せず、変更前後のハッシュを使って復元時の競合を確認します。[接続Adapter](../server/native-connection.ts)と[接続設定のテスト](../tests/native-connection.test.ts)で、構文、再実行、中断、秘密情報の非公開、後続変更の保護を検証しています。

接続の再開では最初に保存した対象を使います。同じCore内で後続の導入が接続を共有している間は、先行導入の復元を拒否し、先に復元する導入IDを返します。

既存資産の導入は、探索結果と進捗をCoreのデータディレクトリーに保存します。再実行時には元パスを含む識別情報を使い、同名だけで統合しません。バックアップの上書き、探索後の内容変更、シンボリックリンクへの置き換え、未知のRuntimeの切り替えを拒否します。Skillの未対応ファイルは欠落させず、切り替えを保留する理由として返します。

初回整理は、ユーザー依頼に基づく一括変更として保存します。`other`を資産種別に追加し、取り込み時には無効状態を保ちます。Skillと補助ファイルの原文・相対配置・出所を保存し、過去の改訂も取得できます。認証情報・Runtime設定・履歴・キャッシュは資産本文へ入れません。

Workflowの工程からRole、Roleの割り当てからModelとRuntime、その条件から下位資産を解決します。Roleから資産への関係、Modelに対する適用条件、Skill間の必須利用・条件付き利用・資料参照を保存します。共有Skillを複数回選んでも本文は重複しません。SkillからRoleやModelを選ぶ経路を削除しました。旧`skill.role`と`skill.taskType`は、既に選ばれた条件の一致検証にだけ利用します。

関係の抽出は資産の保存時に行います。手動指定を保持し、本文から抽出した関係を更新します。本文を変えずに未分類資産をSkillへ変更した場合も抽出します。実行時は保存済みの関係のみを使います。条件が自然言語だけの場合は無条件に展開しません。必須利用と既存の依存を合わせて循環を検出し、相互の資料参照とは区別します。

## 互換性と検証範囲

保存形式の版は引き続き`schemaVersion: 1`です。追加した情報は任意フィールドとして扱い、既存の資産、Snapshot、履歴を読み込み時に書き換えません。`canComplete`のない既存工程は、遷移がない場合に完了できる従来の規則を使います。スターター再追加でも既存資産を上書きしません。

既存のSkillが担当を自動選択する挙動は、上位から選択する新方針に合わせて変更しました。担当が必要な作業はWorkflowで定義します。古い未承認Reviewで実効差分が保存されていないものは、承認前に新しいReviewで提案を確認します。公開MCPの一覧応答は、配列から`items`・`total`・`nextOffset`等を持つページ形式へ変わっています。接続したRuntimeはツール定義を再取得してください。

検証は、一時データディレクトリーを使ったCoreテスト、公開HTTP/MCP接続、ファイルの中断・競合・復元試験、Chromiumによる画面操作で行います。要求文書で記録されていた利用者の実環境フォルダーは、この実装作業では移行していません。

追加設計まで反映した検証は`npm run check`（型検査、製品ビルド、サーバー側141テスト）と`npm run test:ui`（Chromiumでの23テスト）です。いずれも成功しました。Skillの個別取得、指定モデルと不明な実モデルの表示も画像で確認しました。独立レビューで見つかったモデル条件の完了時検証、準備時のSkill使用条件の引き継ぎ、参照先の取得方法、取得量の重複計上、エクスポートへの接続情報混入、Markdownの参照形式、出力後の成果物差し替えには回帰テストを追加しています。

接続設定についても、共有接続の復元順、接続対象が増えた後の再送、設定の公開直後のプロセス終了、バックアップ書き込み中の容量不足・プロセス終了を再現しています。途中のバックアップを完成品として公開せず、記録済みの一時ファイルだけを回収して再開します。任意のハードリンクや後続の編集は引き続き拒否します。

実モデルによる複数工程の開発品質改善、外部Runtimeが独自に持つOS操作の強制、別ホストへの自動アクセスは検証対象ではありません。Runtimeからの実行報告と制約宣言は、そのRuntimeが送った記録として扱います。モデルを起動した事実や品質改善を、Snapshotの存在だけから認定しません。
